# AI 媒体创作工作台设计提示词

```text
你是一名资深产品设计师与前端设计工程师。请为“Short Video Studio（AI 媒体创作工作台）”设计并实现一个可直接使用的 Web 应用界面。它是创作者实际用来生成图片和视频的工作台，不是营销落地页、产品官网或概念海报。

## 产品背景

产品为个人作品集中的真实 AI 媒体生成项目，整合多个服务商的图片与视频模型。用户输入创作描述、选择生成方式与兼容模型、上传参考素材，然后创建真实任务并在页面中查看、播放、打开或下载结果。

页面已有三个同级入口：

1. 视频：文生视频、首帧驱动、首尾帧、多关键帧、多图参考、视频续写、指令编辑、动作迁移、角色替换。
2. 图片：文生图、参考图编辑；支持上传多张素材。
3. Agent：用户输入一句创作描述，先由服务端给出图片或视频生成计划，用户确认后才执行真实任务。

项目默认只展示并调用已确认免费的模型。模型可用性、额度耗尽、排队、生成、完成和失败都是真实状态，界面不能假装已经生成内容。

## 设计目标

让第一次使用的人在 10 秒内理解：

- 这里可以做什么。
- 当前位于视频、图片还是 Agent。
- 现在该先选生成方式、模型，还是上传素材。
- 本次生成会走哪条路径。
- 结果在哪里、当前进度如何、下一步可以做什么。

优先级始终是：创作输入与生成操作 > 当前任务和结果 > 模型与素材说明 > 辅助设置。视觉设计服务于连续创作，不服务于炫技。

## 核心页面结构

### 应用外壳

- 顶部固定但紧凑：左侧显示产品名 `SHORT VIDEO STUDIO` 与小型“真实服务”状态；中间为 `视频 / 图片 / Agent` 三个标签页；右侧放置刷新模型状态、主题/设置等图标按钮。
- 不设计 Hero、营销文案、价格区、用户评价、虚构数据或大幅宣传插画。首屏直接进入工作台。
- 桌面端采用左右两列：左侧为创作工作流与设置，右侧为固定的结果预览与任务状态。右侧保持可见，避免用户提交后找不到结果。
- 页面区块使用清晰的全宽分隔线或自然留白；不要把整个页面拆成一堆漂浮卡片，更不要卡片嵌套卡片。

### 视频工作台

左侧按自然操作顺序组织：

1. `01 生成方式`：用横向可滚动的分组切换“文字创作 / 图片驱动 / 参考一致性 / 视频再创作”，组内显示具体工作流。选中项要同时显示名称和一句真实输入语义，例如“首帧图 + 视频描述”。
2. `02 兼容模型`：按“服务商 + 模型系列”分组，每个系列用紧凑变体选择器切换 Standard、Flash、Turbo、日期版本等。每个模型行应可扫描地呈现服务商、适用场景、时长、清晰度、图片数量和音频能力；精确模型 ID 只做次要信息。
3. `03 描述与素材`：视频描述是最主要输入区。上传区必须使用任务语义而不是笼统的“参考图”：首帧图、尾帧图、关键帧 1-N、人物参考、背景参考、原视频、动作视频、替换人物图。输入 `@` 时显示横向图片菜单，可插入对应的语义标签；已有素材可移除、改序并同步标签。
4. `04 输出设置`：比例、时长、清晰度、音频、水印、负面提示词、随机种子等控件只在当前模型真正支持时出现。不要用禁用控件堆满页面。
5. `生成路径摘要`：在生成按钮前直接显示例如“首帧图 + 描述 -> 模型名 -> 5 秒 / 720P”；缺少素材或描述时，在按钮下以具体、可行动的文案说明，而不是泛化报错。

右侧预览区要随任务状态变化：

- 空闲：显示与当前比例一致的预览画布，提示用户还缺少什么，不使用伪造视频缩略图。
- 排队/生成：显示真实状态、进度和当前模型，不要承诺精确剩余时间。
- 完成：显示视频播放器、打开、下载、重新生成和新建任务操作。
- 失败：保留本次模型、路径和用户输入，展示可读错误、重试和切换模型入口。

### 图片工作台

- 保持与视频页相同的顶部入口、编号、输入逻辑和右侧结果区，避免成为风格不同的另一套产品。
- 工作流仅包括“文生图”和“参考图编辑”。参考图编辑要先展示素材缩略图，再紧凑排列描述框，不能让描述框压在上传区或标签上。
- 输出设置包含清晰度、生成数量与当前模型支持的约束。结果完成后采用整齐网格；每张图提供打开、下载、删除或作为视频首帧继续创作的图标操作。

### Agent 工作台

- 不是聊天机器人界面。它是“计划 -> 确认 -> 执行”的创作编排器。
- 顶部选择“自动判断 / 生成图片 / 生成视频”，中部只有一块清晰的创作描述输入区和“制定生成计划”主操作。
- 计划生成后显示结构化路径：目标媒体、工作流、模型、服务商、规格、提示词摘要和理由。将“确认执行计划”作为唯一高优先级操作。
- 真实生成后沿用图片或视频的状态与结果预览，不新建第二套轮询或下载体验。

## 视觉系统

整体气质：黑色高对比、克制、清晰、轻工业感、专业创作工具。不要做赛博霓虹、玻璃拟态、紫蓝渐变、发光边框、彩色背景球或过度圆润的 SaaS 模板风格。

### 色彩

- 页面背景：`#000000`。
- 次级背景/输入表面：`#080908`、`#101110`、`#151715`，用微小明度差建立层级。
- 主要文字：`#F7F8F4`；次要文字：`#949A94`；辅助文字：`#626762`；边框：`#2B2E2B`。
- 唯一品牌强调色：酸橙绿 `#C6FF4A`，只用于当前选中、主生成按钮、可点击焦点和关键数字。它不应用作大面积背景。
- 成功仅用 `#C6FF4A` 的克制状态提示；警告用 `#FFB800`；错误用 `#FF3B30`。状态颜色不能替代文案。
- 不使用渐变。颜色比例保持黑灰白为主、绿色只负责关键操作与状态。

### 排版与间距

- 中文优先使用 `PingFang SC`、`Microsoft YaHei`、`Noto Sans SC`，英文和数值使用现代无衬线字体。数值、模型 ID、路径摘要可使用等宽字体。
- 工具页面不要用营销级超大标题。页面标题约 24-32px，区块标题约 18-22px，正文 14-16px，辅助信息 12-13px。
- 字间距为 0；保证中文、长模型 ID、错误文案和按钮文字均可换行或截断，绝不重叠。
- 桌面内容区保持稳定网格和一致间距；控件高度、缩略图比例、图标按钮尺寸必须固定，避免任务状态变化导致布局跳动。
- 圆角保持 4-8px；分组面板最多 8px。不要使用药丸形大按钮或超大圆角卡片。

### 组件规则

- 使用 Lucide 线性图标。下载、打开、删除、刷新、播放等常见操作优先使用带 Tooltip 的图标按钮；只有“生成”“制定计划”“确认执行计划”等清晰命令使用图标加文字按钮。
- 模型选择使用列表、分段控制或横向变体切换，不使用多层下拉框把能力藏起来。
- 上传素材区是固定尺寸槽位，支持拖放、上传进度、缩略图、替换和删除；不要只放一个没有上下文的通用上传框。
- 输入框焦点用绿色细边或清晰背景变化；错误在字段附近说明原因；加载按钮保留宽度并显示图标，不让布局抖动。
- 只有重复项目、模态框和真正需要边界的工具可使用卡片。页面章节不要包在装饰性大卡片中。

## 交互与状态

- 设计 Default、Hover、Active、Focus、Disabled、Loading、Empty、Uploading、Queued、Generating、Completed、Failed、Quota exhausted 等全部状态。
- 额度耗尽时，只移除对应模型变体；同系列仍有可用变体时自动切换并告知用户。不要把整个界面变成错误页。
- 每一处模型或工作流切换都应保留仍兼容的输入，清理不兼容素材时需清晰说明。
- 所有异步操作要防止重复提交；提交后主按钮进入处理中状态，仍允许用户查看路径和结果。
- 动效仅用于反馈：150-200ms 的颜色、透明度或 2px 位移过渡即可。禁止大幅弹跳、持续旋转、复杂粒子或自动播放的装饰动画。

## 响应式与可访问性

- 桌面：左侧设置约 60%，右侧预览约 40%。
- 平板：保持双列但缩窄设置；工作流与模型变体允许横向滚动。
- 手机：改为单列，按“当前入口 -> 生成方式 -> 模型 -> 描述/素材 -> 输出 -> 生成 -> 结果”排列；结果区位于生成操作后。素材槽位单列，横向标签和变体不挤压文字。
- 所有图标按钮必须有可访问名称/Tooltip；键盘焦点清晰可见；颜色不是传达状态的唯一方式；保证普通文本对比度和可读字号。

## 输出要求

先梳理现有页面、组件、状态和模型约束，再在不改变真实 API 协议的前提下优化界面。优先复用已有 React 组件、CSS 变量和 Lucide 图标；不要为了视觉效果引入新的 UI 框架。

最终交付应包括：

1. 可运行的桌面、平板、手机界面。
2. 完整的真实状态，而不是静态设计稿。
3. 与当前黑色工业风一致、但信息更清晰和操作更顺畅的样式。
4. 对长文本、模型下架、上传失败、任务失败和无可用模型的处理。
5. 构建与浏览器视口验证结果。
```

## 使用说明
